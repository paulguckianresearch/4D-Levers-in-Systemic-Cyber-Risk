Paper 4D timing pilot v0.2 — 1 November 2026

STATUS AND PURPOSE
This is an explicitly declared exploratory model revision. It adds timing controls around the unchanged Paper 4C v0.27 simulator. It is not a confirmatory experiment and does not supersede the completed six-factor grid. It tests attack opportunity cadence against incident-response mobilisation delay on a small selected set of estates. It does not establish a catastrophe, bifurcation or hysteresis.

THE TWO CONTROLS
Attack period P = 1, 2 or 4 wall ticks. At ticks 1, 1+P, 1+2P, etc., all attack-transition hooks may execute: delivery/source entry, acquisition-stage advancement, credential/control-plane capture and replication, captured-controller pushes, channel pushes, payload triggering, attacker retry/retooling, attacker relation reopening, attacker reconfiguration and impact. A hook with its own native cadence must satisfy both schedules. P=1 executes the original schedule; P>1 throttles opportunities on every listed route. Node mechanics, capability probabilities and topology are unchanged. Existing due-times and ageing thresholds remain wall-clock quantities, so this is NOT a mathematically uniform rescaling of all attack time. The treatment's realised propagation speed must be measured. Initial external compromise is inherited, not delayed. Command/contact reachability is recalculated each wall tick; it is a state query rather than a new attack transition. Phase-switch campaign/delayed profiles are excluded by the revised engine.

Response lag D = 0, 8 or 24 wall ticks. This is ONE mobilisation lag per incident, triggered by the first actionable passive observation, visible in-scope live alarm, or usable signature discovery. After the trigger, reactive action is unavailable until first_evidence + D. Investigation/queue processing (including alarm-driven hunting), reactive blocking, defensive adaptation, tactical clean-up, hand signature updates and pending/rebuild execution all use this gate. Signature discoveries before mobilisation are held and their block-push delay starts at release. Preventive payload repulsion and pre-installed protection remain active; this experiment is about reactive response. Once mobilised, further evidence proceeds normally. This is NOT a delay imposed separately on each report. The choice of one-off mobilisation avoids conflating latency with responder-occupying investigation duration. That duration and responder number stay at their selected/background values.

Passive observation latency is fixed at zero and observation interval at one in this pilot; their original separate settings are not swept. Therefore old-grid collapse probabilities are selection references and are not assumed to reproduce here.

NEUTRAL-SETTING CHECK
P=1, D=0 reproduces inherited outcome dictionaries exactly in 12 checks spanning intrusion, implant, malware and stealer and three seeds, before any configuration selection. Timed passive/alarm/signature fixtures establish that reactive hooks do not run before release. A full-route diagnostic demonstrates that larger periods delay growth (24 runs), though prevention remains active even with reactive defence disabled and some runs do not reach half-compromise. The reported restricted time to half counts those runs at the 168-tick horizon; it is not the conditional mean among only reached runs. Detailed results are in validation.json. No binary comparison proves universal correctness; source audit also identified the complete hook set and the supported attack profiles.

CONFIGURATION SELECTION (AFTER VALIDATION)
Six configurations were selected from the completed old-grid analysis at passive latency zero: closest-to-50% collapse separately at 0, 4 and 16 placements; closest-to-2% and closest-to-98% controls; and the largest late-state starting-condition gap excluding previously selected configurations. Ties use configuration ID. Every selected point is in selection.json with its old-grid collapse estimate. A starting-condition-gap candidate is used here only as a clean-start timing scenario. Starting-state dependence and persistent regimes need separate experiments.

PILOT SIZE
6 configurations x 3 attack periods x 3 response lags x 4 wirings x 4 dynamics seeds = 864 runs. Clean start, intrusion, 100 ordinary estate nodes, chain backbone, 600 wall ticks. Four independent wirings are for development only, not reliable final precision. Larger future runs need a frozen protocol and reserved seeds. Seeds here start at wiring 84001 and dynamics 94001000; previous diagnostic validation uses 83001 and 93001000. Programme-wide seed uniqueness beyond visible records is not certified.

OUTPUT AND MEASUREMENT
One compact JSON record per run with input IDs, first operational collapse, time before first collapse, first evidence, scheduled mobilisation, first response action and contamination immediately before it, first node isolation/reset and its contamination, late/final compromise and service-value loss, alarms, hunting discoveries, queue peak, and realised structure. A cut counts as a response action; it is not asserted to remove a currently used attack path. First-node-containment records isolation of a compromised/infected node or resetting a compromised node. It does not include protection that repels initial infection, nor prove lasting containment. Contamination at action is downstream and must not be treated as an ex-ante predictor without temporal qualification.

Both original collapse stops are disabled; collapse is reconstructed from the original 80% node compromise OR unavailable service-value threshold. Trace collection does not mutate the physical state. Full traces exist transiently in memory only. Selected records (first wiring and first dynamics seed of each of 54 timing cells) keep ticks 1–30 and every tenth tick thereafter. This sharply reduces file size. Summary CSV averages each fully balanced cell; it is descriptive and provides denominators for outcomes conditional on an action occurring. upload_timing_results.zip is produced automatically and contains the compact data, manifest, summary and revision files. Original 4C engine identity is recorded in manifest.json and supplied in this package.

RESUME AND RUN CONTROL
Scientific identity includes code digests, selected configurations, horizon, seed counts/ranges and timing settings. It excludes --workers, --execute, --limit and the output path. Planning then execution and changes in worker count can therefore resume the same experiment. Each completed line is flushed; no partial-line repair or deletion occurs automatically. If a previous line is malformed, stop and repair it with a backup rather than deleting the whole dataset. Run only one writer per output folder. A changed scientific setting requires a new folder. Multiprocessing submits at most twice the worker count simultaneously, rather than queuing the entire experiment.

INTERPRETATION
Compare fixed wall-clock horizon outcomes alongside time-to-collapse: slowing attacks gives fewer attack opportunities by 600 ticks. D/P is a candidate dimensionless relationship, not an assumed universal law. First-evidence timing itself depends on attack trajectory. At the same nominal D/P, background timers and defensive work durations differ relative to attack opportunity cadence. Analyses must check these distinctions rather than infer similarity from a ratio alone. This pilot selects useful ranges; it is not the final model-comparison or catastrophe experiment.
